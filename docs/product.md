# Catchup 产品思路

> **不用刷，重要的不会错过。**<br>
> Stop checking. You won't miss it.

这篇文档讲 Catchup 要解决什么问题、为什么先做 AI、产品应该是什么样、怎么判断做对了。功能和用法见 [README](../README.md)。

## 核心判断

当一个行业的变化速度、信息的分散程度和错过的代价加在一起，超过了人能分出的注意力，用户需要的就不是更多内容，而是一个**替他持续盯着、判断哪些变化对他重要、只在必要时打扰他**的系统。

- **FOMO 是症状，个人相关性才是问题。** 传统内容平台默认用户需要更多内容，所以优化打开率、点击率和停留时长。专业信息的情况正好相反：内容早就过量了，缺的是“哪些可以放心忽略”的确定性。
- **真正的价值是“可以不刷了”。** 用户能停止主动巡检，因为重要的变化会主动找到他。用户因为怕错过而来，因为可以放心不刷而留下。
- **机会不在聚合。** 聚合、摘要、追踪工具已经很多，空白在于自动理解这个人当下真正关心什么。

判断一个行业适不适合这样做，可以看这个式子：

```
怕错过的压力 ≈ 变化速度 × 来源分散程度 × 错过的代价 ÷ 注意力
```

这个值足够高时，“持续监控 + 个性化筛选 + 主动通知”就从锦上添花变成了工作的基础设施。

## 为什么先做 AI

AI 不是最大的市场，但可能是最好的切入点，因为四个条件同时满足：

| 特点 | 在 AI 里的表现 | 对产品的要求 |
|:--|:--|:--|
| 变化快 | 模型、API、框架、benchmark 更新频繁 | 分钟到小时级发现，而不是周报 |
| 来源分散 | 新模型先上 Hugging Face，新框架在 GitHub，新能力在 changelog，新观点在 X / Reddit / 播客，新论文在 arXiv | 需要跨来源的信号层，任何单一媒体都覆盖不全 |
| 长尾有价值 | 一个小众仓库或一篇论文，可能对某位工程师极其重要 | “热门”代替不了个人相关性 |
| 错过有代价 | 技术选型、重复研究、产品判断、职业机会 | 用户愿意为信息优势付费 |

最先服务的人：离前沿最近的 AI 工程师、研究员和创始人。越靠近模型、推理框架、Agent、语音、多模态这些变化快的方向，需求越强。

## 用户今天怎么解决

真正的竞品不是另一个 App，而是一套手工的“信息巡检”：刷 X、小红书看大家在聊什么，刷 Hugging Face、GitHub 看新模型新项目，刷 arXiv 看研究，订 Newsletter 兜底；更主动的人会让 ChatGPT、Claude 定时搜索。

| 方式 | 强项 | 根本问题 |
|:--|:--|:--|
| X / 小红书 | 弱信号来得快 | 为停留时长优化，不为重要性优化，得一直刷 |
| Newsletter | 编辑质量高 | 频率慢，每个人收到的内容差不多 |
| RSS / 提醒 / 追踪工具 | 可控，覆盖广 | 依赖关键词和规则，要自己配置、维护 |
| 大模型定时任务 | 用自然语言，可定制 | 仍然靠写 prompt，通用而不懂行业里的事件 |

它们的共同缺陷：都要求用户先知道自己想监控什么，把脑子里隐含的工作背景翻译成关键词、规则或 prompt。这是用户自己搭的自动化，不是真正的个性化。

## 产品定义：从 Feed 转向 Watch

不是帮用户看更多，而是让用户可以不看。三个出发点，而不是 Feed-first：

- **Push-first**：重要的变化主动送到用户面前，而不是等用户来刷。
- **Event-first**：围绕事件而不是文章。十篇报道同一件事，对用户来说是一件事；三天后出现新 benchmark、许可证变化或官方澄清，也归到同一件事的时间线里。
- **Follow-up-first**：用户一键追踪之后，不再重复推同一件事，只推实质进展：benchmark、官方澄清、issue、许可证、兼容性、价格、社区复现等。

要做到这些，系统得同时解决两个难题：把全网的信号去重、合成事件；判断一件事对这个人有多重要。为此，系统需要从五个方面理解用户：

| 方面 | 含义 |
|:--|:--|
| 长期兴趣 | 长期工作的领域、技术栈、关注的公司和项目、研究方向 |
| 当前任务 | 最近 1～4 周在做什么，权重高于长期兴趣 |
| 不想看的 | 明确不想看什么，什么不值得打扰 |
| 来源偏好 | 偏好官方源、论文、代码还是社区讨论，不同来源可信度不同 |
| 时效要求 | 有的事要分钟级知道，有的每天看一次就够 |

**优化目标不是点击率。** 要估计的不是“用户会不会点”，而更接近“用户事后会不会后悔错过，减去打扰他的代价”：

```
P(用户会后悔错过这件事 | 事件, 用户当前的背景) − 打扰的代价
```

这自然得出：推得越少越好，但漏掉真正重要的事代价极高。

## 体验原则：少配置、讲清楚、会跟进

- **少配置**：可以先选几个大类，但不让用户写二十个关键词；从阅读、收藏、追踪、忽略、提问里慢慢学，并允许用户查看、修改、删除系统对他的理解。
- **讲清楚**：每条推送都说得出“因为你最近关注 X，而这次变化涉及 Y”。用户可以一键调低某个兴趣、屏蔽某类事件、提高某类来源的优先级。透明可控既让人信任，也利于个人信息和算法推荐方面的合规。
- **会跟进**：追踪之后只推实质进展，并把一件事的来龙去脉连成时间线。

首页应该是正在发展的事件、今天的要紧变化和追踪中事件的时间线，从结构上避免退化成“AI 版今日头条”。

## 技术重心：Agent 只是执行层

| 环节 | 职责 | 真正的难点 |
|:--|:--|:--|
| 来源采集 | 抓 GitHub、HF、arXiv、博客、X、Reddit 等 | 覆盖面、延迟、反爬、来源可靠性 |
| 事件识别 | 聚类、去重，识别“发生了什么变化” | 合并同一件事、认出旧闻、发现增量 |
| 交叉核实 | 多个来源互相印证，标出官方来源 | 速度和可信度之间的平衡 |
| 个人排序 | 用事件和用户背景一起排序 | 长短期兴趣、负反馈、打扰的代价 |
| 后续跟进 | 对追踪中的事件持续搜索 | 判断有没有实质进展 |
| 简报 | 很短的摘要，加上“为什么和你有关” | 可核实、不夸大、保留出处 |

用多少个 Agent、怎么编排，很容易被基础模型和现成框架追平，不该放进产品叙事。长期的壁垒更可能来自三样东西：

- **兴趣图谱**：用户关心什么、正在做什么。
- **事件图谱**：世界上发生了什么、后来怎么发展。
- **评测和数据积累**：哪些推送被用户认为“真值得”。

## 怎么判断做对了

第一阶段不求覆盖整个 AI 世界，而是在一小群人里先建立起高度信任：

1. 自动建立基础的兴趣画像，并允许用户直接修改。
2. 分钟到小时级地抓取信号，合成事件。
3. 每天只推极少量“错过会后悔”的事件，并说明为什么和他有关。
4. 一键追踪后，只推真正的新进展，并维护时间线。

来源分层：GitHub、Hugging Face、arXiv 和各家官方博客、changelog 是一级来源，是事实依据；Hacker News、Reddit、X 是发现弱信号的地方，内容要回到一级来源核实；小红书、公众号、技术社区可以说明“这个话题正在升温”，但不把二手内容当作事实。

| 指标 | 定义 | 为什么重要 |
|:--|:--|:--|
| 本会错过率 | 推送中，用户表示“没有 Catchup 我会错过”的比例 | 直接衡量核心价值 |
| 高价值命中率 | 推送后被收藏、追踪或深入阅读的比例 | 避免通知疲劳 |
| 关键漏报率 | 用户事后自己去搜的重要事件里，系统没有提前发现的比例 | 衡量“不会错过”是否可信 |
| 信号到达时间 | 一级来源出现可信信号，到用户收到推送的时间 | 对应“十分钟内知道”的预期 |
| 打扰负担 | 每人每天收到的推送数和屏蔽率 | 越少越好，前提是不漏关键事件 |

**最有力的验证不是日活，而是行为变化**：用户连续一周少刷了 X、小红书、HF、GitHub，却不觉得自己错过了重要信息。

做用户研究时，不问“你会不会用一个 AI 新闻 App”，而是看目标用户过去 7 天真实的信息习惯：每天打开哪些平台、为什么打开、担心错过什么、哪条消息知道得太晚、有没有自己写过订阅、RSS 或 agent。重点验证三件事：

1. **怕错过是否足够频繁**：用户是否每周多次主动去确认“有没有新东西”。只是偶尔刷的话，推送产品价值有限。
2. **个性化是否明显好过手工追踪**：如果用户更愿意自己写 prompt 和关键词，兴趣画像的优势就不成立。
3. **用户是否信任“少推”**：如果始终要完整的信息流，说明他要的是聚合，不是安心。

## 边界与延展

**竞争**：[AyeWatch](https://ayewatch.ai/)、[Zetik](https://www.zetik.ai/)、[Particle](https://particle.news/blog/introducing-particle-the-news-organized)、[Feedly](https://feedly.com/market-intelligence/pricing) 等相邻产品已经证明了“主动监控 + 个性化”的需求，[ChatGPT Pulse](https://openai.com/index/introducing-chatgpt-pulse/) 也说明大家正从“用户来问”走向“系统主动带来个性化更新”。Catchup 要争的不是“第一个 AI 监控工具”，而是这几样的组合：AI 领域足够深的来源、自动推断用户没说出口的兴趣、分钟级发现事件、一键持续追踪、极低的通知噪声。

**合规**：先做 AI 和科技方面的专业信息、优先官方和技术来源，可以显著降低早期的复杂度，但不等于自动豁免。个性化从第一天起就做到可解释、可关闭、可删除，“为什么推给我”是核心界面；摘要保持简短、只讲事实，并链接回原始来源；用户的兴趣数据尽量存在境内，交给境外模型时只给最少、抽象过的兴趣描述。以上是产品设计上的考虑，不构成法律意见。

**商业**：不卖“更多信息”，也不以广告和无限的内容消费为主。能收费的是两件事：省下主动巡检的时间，提供用户担心错过的信息优势。路径是先服务个人专业用户（AI 工程师、研究员、创始人、产品经理、投资人、独立开发者），再到团队（共享关注清单、团队背景、推送到 Slack / 飞书 / 企业微信），再把事件图谱和实时信号作为接口提供给其他 Agent 或企业系统。

**跨行业**：AI 只是第一个被信息速度压垮的行业。以后按“变化速度和错过的代价”而不是内容类别选择下一个领域：

| 行业 | 变化速度 | 错过的代价 | 可以盯的对象 |
|:--|:--|:--|:--|
| AI / 机器学习 | 极高 | 高 | 模型、API、论文、代码仓库、benchmark、招聘和融资 |
| 网络安全 | 极高 | 极高 | 漏洞（CVE）、利用代码、供应链风险、厂商补丁 |
| 投资 | 高 | 极高 | 公告和财报、管理层表态、产品和供应链信号 |
| 生物医药 | 高 | 极高 | 论文、临床试验、监管、专利 |
| 开发者工具 | 高 | 中高 | 新版本、破坏性变更、兼容性、价格 |

**定位**：Google 是“想知道时去搜”，ChatGPT 是“想弄懂时去问”，Catchup 想成为“不用主动去看，因为它一直替你看着”。长期的品类不是“新闻”，而是个人情报（Personal Intelligence）。

## 在项目里怎么落地

| 思路 | 现在的做法 |
|:--|:--|
| Event-first | 规则聚类加模型判断，把同一件事合成一个事件，事件有固定 id（`pipeline/events.py`、`pipeline/brief.py`） |
| Follow-up-first | 持续追踪只推实质进展（`pipeline/follow.py`）；对话里暂时没答案的问题，之后有报道回答了就写回去（`pipeline/answers.py`） |
| 理解用户 | 不用写关键词：从对话、反馈和阅读里沉淀六类记忆（长期关注、正在做、不想看、偏好来源、不想看的来源、写法），可以查看、修改、删除、整体关闭（`personal.py`） |
| 讲清楚 | 排序的每一项加分都附带理由（`pipeline/ranking.py`）；“想多看”会告诉你记住或加强了哪条记忆 |
| 少打扰 | 23:00～8:00 只推重大消息，其余合成早报；只出现在榜单或创投媒体上的事件，要被判为“重要”才推送 |
| 来源分层 | 来源分 `official`（官方）、`primary`（一手技术源）、`signal`（弱信号）三级，影响排序（`config.json` 的 `tier`） |
| 摘要有出处 | 简报先读主来源原文再写，对话回答标注出处，报告里的引语出处和链接由代码填写 |
